# Multi-Agent Orchestration — Competitive Landscape

Category: tools that run multiple AI coding-agent sessions concurrently and give a human one surface to supervise them. Dominant pattern: **git-worktree-per-agent + a supervisor process/UI that tracks status and gates the merge back to a shared branch**. Two axes split the field — (1) how isolation is achieved (worktree vs. container vs. microVM vs. tmux pane) and (2) how much autonomy the supervisor has (human clicks merge vs. a merge-queue/reviewer agent auto-merges on green CI).

## Per-Project Entries

### Orca — [stablyai/orca](https://github.com/stablyai/orca)
License: MIT. Concurrency: worktree-per-agent, "fan one prompt across five agents" comparison mode; also SSH-remote worktrees. Supervisor: Electron desktop app + native mobile companion (iOS/Android) for remote steering. Merge: human reviews diffs with inline annotate-and-ship; no auto-merge. Differentiator: any-CLI-agent support (30+ named agents incl. omp) plus an embedded Chromium "Design Mode" that turns clicked DOM elements into agent prompts. Source: README.

### Herd — [NickGuAI/Herd](https://github.com/NickGuAI/Herd)
License: AGPL-3.0 (commercial license available). Concurrency: process-per-"worker" on registered machines (local, SSH, Tailscale); durable "commander" identities own workers. Supervisor: self-hosted web control plane ("Command Room"), Node/pnpm daemon on Node's built-in SQLite. Merge: not merge-centric — action-policy gate (auto-run / queue-for-review / block) on external actions, not on git merges. Differentiator: bundled "commander marketplace" (Asina/Einstein/Alfred personas) with `COMMANDER.md` + skill manifests. Source: README.

### Taskplane — [HenryLach/taskplane](https://github.com/HenryLach/taskplane)
License: MIT. Concurrency: git-worktree lanes inside dependency-ordered "waves" (DAG), mono- and poly-repo, dynamic segment expansion for polyrepo. Supervisor: pi-package CLI + live SSE web dashboard (`taskplane dashboard`). Merge: automated merge into a dedicated `orch` branch per wave; explicit `/orch-integrate` brings it into the user's working branch. Differentiator: 4 named agent roles (supervisor, worker, reviewer, merger) with worker-invoked `review_step` inline reviews using a different model than the writer. Source: README.

### CompozyOS — [compozy/compozy](https://github.com/compozy/compozy)
License: MIT. Concurrency: home-scoped daemon owns "Sessions" and "Loop" runs across ACP-compatible CLIs (Claude Code, OpenClaw, Hermes); no worktree isolation claimed in README — sessions are daemon-tracked, not filesystem-isolated. Supervisor: single Go binary + web shell + CLI/HTTP/SSE/UDS/MCP surfaces, all reading the same daemon-owned state. Merge: not applicable — no PR/merge concept in the README; work "survives the terminal" via daemon-owned session state instead. Differentiator: "Compozy Network" lets sessions discover peers and delegate work with typed messages + receipts over a documented protocol (`compozy-network/v0`). Source: README.

### amux — [andyrewlee/amux](https://github.com/andyrewlee/amux)

Merge: explicit `git merge --no-ff` keystroke (`M`) in the primary checkout, with conflict-file listing and abort offer — never auto-merges, never pushes. Differentiator: repo-supplied `.amux/workspaces.json` setup/run/archive scripts are content-hash-gated — a changed script re-requires human trust approval before amux will execute it. Source: README.

### Genie — [automagik-dev/genie](https://github.com/automagik-dev/genie)
License: MIT. Concurrency: fans agents out through the *active client's own native subagents* (Claude Code / Codex role agents) — Genie itself has no worker process; worktree isolation is "orchestrator-arranged per the dispatch contract," i.e. optional, not structural. Supervisor: 16-command CLI + kanban board derived live from one per-repo SQLite file (`genie.db`), shared across all worktrees of a repo via git's common dir. Merge: no built-in merge automation; state changes serialize through `genie.db` transactions, one CLI invocation each. Differentiator: reviewer is a separate subagent from the writer by design contract ("reviewer ≠ engineer"), and only the orchestrator is allowed to call `genie task done`. Source: README.

### Pane — [dcouple/Pane](https://github.com/dcouple/Pane)

Supervisor: Go daemon + Bubble Tea full-screen TUI (`oat ui`) plus a benchmark harness. Merge: **merge queue is a first-class agent role** — watches CI, merges on green, spawns a fixer worker on red, enters "emergency mode" if `main` breaks; forks use a PR-shepherd role instead. ### Swarm-IOSM — [rokoss21/swarm-iosm](https://github.com/rokoss21/swarm-iosm)

## Cross-Cutting Patterns

1. **Git-worktree-per-agent isolation.** Dominant structural pattern (Orca, Taskplane, amux, Pane, emdash, AgentOS, CCManager, Agent Deck). Solves "two agents editing the same file" by giving each agent its own checkout and branch; conflict resolution deferred to merge time. Source: all listed READMEs.
2. **Container/microVM isolation as the harder alternative.** cspace (Docker devcontainer + firewall), Handler (Docker + Firecracker + 6 cloud backends), Harness Kanban (dev-container-per-worker), IDEKUBE (Kubernetes pods). Buys stronger security boundary (egress allowlists, no shared kernel) at the cost of boot latency and infra complexity — Handler's README calls out sub-5s Firecracker boot as a specific engineering win over this cost.
3. **Dependency-ordered wave/DAG dispatch.** Taskplane ("waves, lanes, tasks"), OAT (implicit via worker independence), Swarm-IOSM ("continuous dispatch loop, no artificial wave barriers" — an explicit *rejection* of fixed waves in favor of eager dispatch as soon as a task's deps clear).
4. **Supervisor/worker/reviewer/merger role split.** Taskplane (4 named roles), OAT (supervisor + merge-queue + workers + PR-shepherd), Genie ("reviewer ≠ engineer" contract), Swarm-IOSM (Explorer/Implementer/Architect subagent types). Consistent theme: the agent that writes code is never the agent that approves it.
5. **Merge-queue-as-agent with CI gating.** OAT's merge-queue role watches CI, auto-merges on green, spawns a fixer on red, and has an "emergency mode" for a broken `main`. This is the most autonomous merge pattern found — most other tools stop at "open a PR" or an explicit human keystroke (amux's `M`).
6. **File-level lock/conflict detection before write.** Swarm-IOSM's "Touches → Locks → Gates → Done" hierarchical file/folder lock model; Paragents' "preflight conflict checks" for output conflicts. Both act *before* a write lands, not as post-hoc diff review.
7. **Cost/token budget guardrails.** Swarm-IOSM (default $10 track budget), Genie omni bridge default-off cost controls, Agent Deck's cost dashboard (`$` key) — budget visibility is table stakes but automated budget *enforcement* (hard stop, not just display) is rarer; Swarm-IOSM is the clearest example.
8. **Zero-token dormancy after handoff.** OAT's workers go fully dormant (zero API calls) after opening a PR; daemon polls GitHub externally and only wakes the worker on a real signal (CI fail, new comment, merge). Distinct from "idle" — this is a designed cost optimization, not just an unattended state.
9. **Approval / action-policy gating with escalating enforcement.** Herd's three-way action policy (auto-run / queue-for-review / block); Paragents' ask/deny/needs_approval state machine; CCManager's Haiku-verified auto-approval with mandatory manual fallback on any uncertainty.
10. **Remote/mobile supervision channel.** Orca (native iOS/Android companion app), Agent Deck (Telegram/Slack/Discord conductor), Pane (browser app at runpane.com/app + SSH/Tailscale daemon), Genie (`genie omni` WhatsApp bridge with ed25519-signed handshake). Consistent shape: a lightweight remote client talks to a resident daemon on the dev machine, never runs the agent itself.
11. **AI-classified session state instead of regex heuristics.** Handler's small-LLM terminal-tail classifier (`needs_input`/`working`/`error`/`done`/`idle`) vs. the more common pattern-matching approach in CCManager/amux/Agent Deck. Only Handler explicitly frames this as an LLM classification step rather than output pattern-matching.
12. **Fork-with-inherited-context.** Orca and Agent Deck both let a user fork a running session and continue from the same conversation history (Agent Deck explicitly ties this to the underlying CLI's own fork support, e.g. `codex fork`), distinct from starting a fresh worker with a written brief.
13. **Skill/task marketplace bundled with the orchestrator.** Herd ships a "commander marketplace" with pre-built personas (`COMMANDER.md` + skill manifest + memory seed); Genie's plugin skills are the product itself, versioned and digest-verified per install.
14. **Trust-gated execution of repo-supplied automation.** amux content-hash-approves `.amux/workspaces.json` before running its scripts, re-gating on any change; Genie's Codex hooks bind exact launcher SHA-256 so a binary change produces a new, unapproved hook definition. Both patterns exist specifically to stop a malicious/compromised repo from smuggling arbitrary command execution through orchestrator config.

## Anti-Patterns

- **Shared mutable workspace with no lock or worktree isolation.** Paragents runs multiple sessions against one reused agent instance in a single process with no filesystem isolation and is explicitly labeled "not production-ready" in its own README — the project's own docs cite this as the open gap versus claude-code's more mature model.
- **Auto-merge with no CI gate.** None of the researched projects do this (all merge automation found — OAT, Taskplane — is CI-gated), but it's the failure mode every merge-queue design explicitly guards against; worth naming as the thing *not* to build.
- **Fire-and-forget subagent dispatch with no reviewer.** Anti-pattern implicit in the "reviewer ≠ engineer" design choices of Genie, Taskplane, and OAT — the pattern they're all reacting against is a single agent both writing and self-certifying its own diff.
- **No budget guard on parallel fan-out.** Swarm-IOSM's README explicitly frames itself against unattended production use without a cost cap; unmetered parallel dispatch is the implied failure mode ("not safe to run unattended on production repos").
- **Terminal-multiplexer coupling without a state model.** amux/CCManager both note this as their reason for existing versus tmux-only workflows — a plain tmux/screen session gives no structured signal of "waiting for input" vs. "actively working," forcing manual polling across every pane.
- **Trusting repo-supplied scripts unconditionally.** The failure mode amux's content-hash trust gate and Genie's hook SHA-256 binding both defend against: a compromised or malicious repo silently gets arbitrary code execution through an orchestrator's own automation surface.

## Pattern to Apply to omp-deck

1. **Pattern: Task-scoped worktree isolation for parallel dispatch.**
   Slot: Tasks kanban (`apps/web/src/views/TasksView.tsx`, `apps/server/src/db/tasks.ts`, `apps/server/src/routes-tasks.ts`).
   UX: a "Dispatch parallel" action on a task card opens N git worktrees (one per candidate approach or per assignee), each backed by a new `AgentBridge.createSession({cwd})` call; each worktree gets its own kanban sub-lane under the parent task.
   Effort: L (needs worktree lifecycle management server-side, not present today). Impact: L (this is the single most-requested capability across every researched competitor).
   Acceptance: creating a task with `dispatch: {branches: 3}` produces 3 sibling git worktrees under the repo and 3 linked sessions visible in the Tasks kanban, each independently steerable.

2. **Pattern: Merge-queue-as-Routine step, CI-gated.**
   Slot: Routines V1 (`apps/server/src/routines/v1-runner.ts`, `apps/server/src/routines/steps/`), new step type alongside `run`/`http`/`transform`.
   UX: a `merge_gate` routine step that watches a linked task's branch for CI status and either merges (`git merge --no-ff`) or spawns a follow-up "fixer" step referencing the same task on failure.
   Effort: M (new step type + git integration; reuses existing `apps/server/src/git-service.ts`). Impact: L (closes the loop OAT and Taskplane both treat as their core value).
   Acceptance: a routine run with a `merge_gate` step transitions a task's kanban column to "Merged" only after a configured check command exits 0; a nonzero exit appends a "Needs fix" comment via `routes-tasks.ts` instead of silently stalling.

3. **Pattern: Reviewer ≠ writer contract for agent-authored tasks.**
   Slot: Tasks (task metadata) + Routines (`agent` step in `apps/server/src/routines/steps/agent.ts`).
   UX: a task option "require independent review" that forces a second `agent` routine step, model-pinned to a different `ModelRef` than the writer step, before the task can move to "Done."
   Effort: S (routine step already exists; add a task-level flag gating the Done transition). Impact: M (directly ports Genie/Taskplane's most-cited quality-gate pattern).
   Acceptance: attempting to move a "review required" task to Done via `routes-tasks.ts` without a passing review-step run returns 409, same shape as the existing plan-approval 409 pattern in `bridge/types.ts`.

4. **Pattern: File-level touch/lock declaration before parallel writes.**
   Slot: Routines concurrency (`apps/server/src/routines/concurrency.ts`) — extend beyond run-level concurrency caps.
   UX: no new UI surface required initially — a `touches: string[]` glob list on a routine step that the runner checks against every other in-flight step's declared touches before dispatch; conflicting steps queue instead of racing.
   Effort: M (concurrency.ts already exists as the natural extension point; needs glob-intersection logic + queueing). Impact: M (prevents the exact race Swarm-IOSM's lock model and Paragents' preflight checks both target).
   Acceptance: two routine steps both declaring `touches: ["src/api/**"]` in the same run never execute concurrently — `routines.test.ts` gets a new case asserting serialized execution order on overlapping globs.

5. **Pattern: AI-classified session status instead of pure state-machine polling.**
   Slot: Gholam (`apps/gholam/src/`) as a lightweight classifier service, surfaced via `apps/web/src/lib/gholam-chat-api.ts` into the Tasks kanban card badge.
   UX: kanban card status dot gains a 4th state beyond running/waiting/idle/error — an amber "needs attention" classification driven by Gholam tailing recent session output, matching Handler's LLM-classification pattern rather than the terminal's own state signal alone.
   Effort: S (Gholam already exists as a chat-sidecar; this is a new prompt template + polling job, not new infra). Impact: S (nice-to-have polish, not a structural gap).
   Acceptance: a session whose last 20 lines of output contain an ambiguous question (not matched by the existing state-machine heuristics) still surfaces "needs attention" on its kanban card within one Gholam poll interval.

6. **Pattern: Mobile/remote supervision channel via existing bridge supervisor.**
   Slot: `apps/server/src/bridge-supervisor.ts` (BridgeSupervisor, already supervises standalone Telegram bridge processes) + `apps/bridges/telegram/`.
   UX: extend the existing Telegram bridge with task-approval buttons (approve/deny inline keyboard) wired to the same `respondToPlanApproval`/`respondToUiDialog` bridge methods the web UI uses — no new transport, reuse the existing approval-response contract in `bridge/types.ts`.
   Effort: S (transport and approval plumbing both already exist; this is wiring, not new architecture). Impact: M (closes the gap versus Orca's mobile companion, Agent Deck's conductor, Genie's Omni bridge — all three treat this as a headline feature).
   Acceptance: a `plan_proposed` frame sent to a session with an active Telegram bridge produces an inline-keyboard message in Telegram; tapping "Approve" calls the same `respondToPlanApproval` path the web UI's approval card uses, verified by a shared bridge-supervisor test.

7. **Pattern: Repo-script trust gate for routine/task automation.**
   Slot: Routines (`apps/server/src/routines/sandbox.ts`, already the sandboxing entry point).
   UX: no new UI — when a routine's `run`/`agent` steps are sourced from a repo-committed YAML (not authored in the deck UI), hash the file content on first execution and require re-approval (a one-time confirm in the Routines inspector) whenever the hash changes.
   Effort: S (sandbox.ts is the natural home; needs a hash-store + one gating check before dispatch). Impact: M (directly closes the attack surface amux's and Genie's trust gates both name as their reason for existing).
   Acceptance: editing a checked-in routine YAML's `run` step and re-triggering it via `routes-routines.ts` blocks execution with an "approval required" state until a human confirms in the Routines inspector; unchanged routines execute without re-prompting.

8. **Pattern: Cost/budget guard visible per-task, enforced not just displayed.**
   Slot: Routines budget (`apps/server/src/routines/budget.ts`, already tracks budget) + Tasks kanban card.
   UX: surface the existing routine budget as a per-task badge in Tasks kanban (reusing `tasksChangeCounter` live-refresh pattern already in `store.ts`), and make budget-exceeded a hard stop (routine run transitions to "blocked," not silently continuing) rather than advisory-only.
   Effort: XS (budget.ts tracking already exists; this is a UI surface + one enforcement branch). Impact: S (parity feature — Swarm-IOSM and Agent Deck both treat budget visibility as baseline, but omp-deck already has the tracking half built).
   Acceptance: a routine run whose spend crosses its configured budget ceiling transitions to a new "budget_exceeded" status visible on the linked task's kanban card, and the routine runner refuses to dispatch further steps in that run until a human raises the ceiling.
