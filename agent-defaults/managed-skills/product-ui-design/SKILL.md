# Product and UI Design

## Workflow
1. Define user, job, permissions, states, and success metric.
2. Map information architecture and critical flows before styling.
3. Reuse the repository design system; preserve intentionally distinct product surfaces.
4. Specify tokens, components, content, loading/empty/error states, responsiveness, RTL/i18n, keyboard and screen-reader behavior.
5. Implement with semantic HTML and native platform features first.
6. Verify in a real browser at representative viewport sizes and interaction states.

## Quality
No generic dashboard filler, placeholder interactions, inaccessible custom controls, or design decisions hidden from implementers. Keep visual hierarchy deliberate and performance-aware.

## Freshness
Use current framework and accessibility documentation for version-sensitive implementation.

## Archived references
Specialized design styles, Next.js/UI libraries, wireframes, slides, and project design systems remain archived for on-demand reading.
